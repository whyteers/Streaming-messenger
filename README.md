# Streaming Messenger

Небольшой C++17-проект для Windows: десктопный мессенджер с **трансляцией экрана** в реальном времени, текстовым и голосовым чатом. Захват экрана идёт через **DXGI Desktop Duplication**, кодирование — через **NVENC** (или резервный CPU-кодек x264), доставку обеспечивает отдельный TCP-релейный сервер.

> Проект находится в активной разработке: часть модулей (авторизация, REST API, файловая БД) пока подготовлена, но не подключена к собираемым целям CMake.

## Возможности

### Клиент (`client.cpp`)

- Две роли: **Viewer** (приём и отображение видео) и **Broadcaster** (захват и отправка экрана), переключение без перезапуска.
- Захват экрана: DXGI Desktop Duplication + D3D11, выбор адаптера NVIDIA при наличии.
- Кодирование:
  - **NVENC** (аппаратное, H.264, low-latency пресеты, CBR, асинхронное кодирование, 4 поверхностей);
  - **CPU x264** как запасной вариант (`ultrafast` + `zerolatency`).
- Декодирование: **D3D11VA** с автоматическим откатом на CPU, очередь кадров с ограничением размера.
- Настройки в UI: разрешение (1280×720 / 1920×1080 / 2560×1440), FPS (15–60), битрейт (1000–20000 кбит/с), выбор кодека, IP сервера. IP можно передать аргументом: `client.exe 192.168.1.10`.
- Интерфейс на SDL2 + ImGui (тёмная тема, кириллический шрифт), окно видео, статистика FPS/битрейта/очереди и журнал событий.
- Голосовой чат через SDL Audio (микрофон, голосовая активация VAD) и текстовый чат в том же TCP-соединении.

### Релейный сервер (`relay_server.cpp`)

- Три TCP-порта:

  | Порт | Назначение |
  |------|------------|
  | `8080` | зрители (получение видео) |
  | `8081` | чат и голос |
  | `8082` | широковещатель (отправка видео) |

- Кольцевой буфер на 30 кадров: новые зрители начинают с последнего ключевого кадра (IDR), отставшие зрители получают счётчик потерь.
- Одновременно активен только один широковещатель.
- Ограничение аудиопакетов (до 100 пакетов/с на клиента), рассылка текста всем, голос — всем кроме отправителя.
- Раз в секунду печатает статистику: активность вещателя, число зрителей, Rx/Tx FPS и битрейт, потери.
- Зависимости: только Winsock2 и WinMM.

## Структура репозитория

| Файл | Назначение |
|------|------------|
| `client.cpp` | SDL2/ImGui-клиент: DXGI-захват, NVENC/x264, H.264-декодер, голос и чат |
| `relay_server.cpp` | TCP-релей: видео, чат, голос, статистика |
| `crypto.cpp` / `crypto.h` | SHA-256, генерация токенов, хеширование паролей (соль + 20000 итераций) |
| `database.cpp` / `database.h` | Пользователи, сессии, комнаты; простое хранилище в текстовом файле |
| `http_api.cpp` / `http_api.h` | HTTP-сервер с endpoints регистрации/логина/комнат (заготовка) |
| `third_party/nvcodec/nvEncodeAPI.h` | Заголовок NVIDIA Video Codec SDK для NVENC |
| `CMakeLists.txt` | Сборка `relay_server` и (при наличии зависимостей) `client` |

## Требования

- **Windows 10/11**, Visual Studio с поддержкой C++ (рекомендуется MSVC).
- **CMake ≥ 3.20**.
- Для клиента:
  - FFmpeg **shared**-сборка для Windows (например, [BtbN FFmpeg-Builds](https://github.com/BtbN/FFmpeg-Builds/releases), `win64-gpl-shared`): нужны `include/`, `lib/`, `bin/` (`avcodec`, `avutil`, `swscale`; для CPU-кодирования — `libx264`);
  - NVIDIA GPU и драйвер с поддержкой NVENC — только для режима NVENC (иначе можно выбрать CPU x264);
  - SDL2 2.30.9 и ImGui 1.90.9 CMake скачает сам через `FetchContent` (нужен интернет при первой конфигурации);
  - `nvEncodeAPI.h` уже лежит в `third_party/nvcodec/`.
- Для сервера: дополнительных библиотек не требуется.

## Сборка

Клонируйте репозиторий и настройте проект, указав путь к распакованной shared-сборке FFmpeg:

```powershell
git clone https://github.com/whyteers/Streaming-messenger.git
cd Streaming-messenger
cmake -S . -B build -DFFMPEG_ROOT=C:/libs/ffmpeg-shared
cmake --build build --config Release
```

Готовые бинарники будут в `build/Release/`. Целевая сборка `dist` дополнительно копирует `client.exe`, `relay_server.exe` и нужные DLL в папку `builds/`:

```powershell
cmake --build build --config Release --target dist
```

Если `FFMPEG_ROOT` не задан или неполный, CMake выведет предупреждение и **соберёт только `relay_server`**. То же можно сделать явно:

```powershell
cmake -S . -B build -DBUILD_CLIENT=OFF
cmake --build build --config Release --target relay_server
```

> При сборке через Visual Studio проверьте, что в проекте выставлена кодировка UTF-8 (`/utf-8` задаётся в CMake, комментарии в исходниках на русском).

## Запуск

1. Запустите `relay_server.exe` — в консоли появятся строки ожидания подключений на портах `8080`, `8082`, `8081`.
2. Запустите `client.exe` (можно с IP сервера: `client.exe 127.0.0.1`).
3. На вкладке **Control** укажите `Server IP` и нажмите:
   - **Start Viewer** — смотреть трансляцию;
   - **Start Broadcast** — передавать свой экран.
4. Для чата введите имя пользователя и нажмите **Start voice**; сообщения отправляются по Enter или кнопке **Send**. Включение микрофона и голосовой активации управляется чекбоксами.

Не забудьте разрешить входящие TCP-подключения на порты `8080`–`8082` в брандмауэре Windows.

## Протокол (кратко)

- Видео и чат передаются по TCP: 4 байта длины payload (little-endian), затем сами данные.
- Кадры видео — H.264 (Annex-B); релей ищет NAL-тип 5 (IDR), чтобы определить ключевой кадр.
- Чатовый кадр начинается с байта типа: `0x00` — логин, `0x01` — текст, `0x02` — PCM, `0x03` — Opus.

## Авторизация и REST API (в разработке)

Модули `crypto`, `database` и `http_api` реализуют:

- хеширование пароля `v1$<salt>$<hash>` (SHA-256, соль 16 байт, 20000 итераций) и токены сессий (24 часа / 30 дней при `remember`);
- хранение пользователей, сессий, комнат и участников в текстовом файле;
- endpoints: `GET /api/health`, `POST /api/auth/register`, `POST /api/auth/login`, `POST /api/auth/logout`, `GET /api/auth/me`, `GET|POST /api/rooms`, `POST /api/rooms/{id}/join|leave`, `DELETE /api/rooms/{id}`;
- проверку токена `TOKEN <token>` при подключении к видео/чату (с временным анонимным доступом, если пользователей ещё нет).

На текущий момент эти модули **не добавлены в исходники целей CMake и не вызываются из `main()`** — это заготовки для будущей интеграции.

## Известные ограничения

- Только Windows (Winsock2, DXGI, D3D11, NVENC/WinMM).
- Видео, голос и чат передаются без шифрования; TLS и сквозное шифрование пока не реализованы.
- Один активный широковещатель на сервер.
- Хранение данных — простой текстовый файл, не полноценная СУБД.
- Ручная установка FFmpeg и его зависимостей; GUI-установщик отсутствует.
